Codex CLI: Install, Sign In, Verify, and What Breaks

Getting the codex cli onto a Mac takes one command; getting it onto an Arm Linux box takes five. Both sequences, plus the version and sign-in checks that catch a bad install.

Straight answerInstallation is genuinely simple on macOS and only slightly less so on Arm Linux, and the failures people hit are almost always an old Node runtime or an ambiguous sign-in choice rather than the tool itself. You need Node 18 or later, one package manager command, and a decision about whether to authenticate with a ChatGPT plan or an OpenAI API key, because that choice decides which meter you spend against. Where a terminal agent does not help is the empty directory: there is no codebase to reason about yet, and Begin.sh covers that case by turning a prompt or a URL into a downloadable static site or Expo app.

Installing the codex cli on macOS

Two supported routes. With npm, a single global install does it: npm install -g @openai/codex. With Homebrew, brew install --cask codex achieves the same thing and keeps updates inside brew, which matters if you already manage developer tooling that way. Before either, check the runtime. Arm's install guide, last updated on 7 September 2026, states plainly that Node.js 18 or later is required, and a stale system Node is the most common reason a global install appears to succeed and then fails on first run. Run node --version first. If the answer starts with a number below 18, fix that before touching the package manager, not afterwards. A minute spent on the check saves the twenty minutes people otherwise spend reinstalling a package that was never the problem.

Arm Linux is a documented target, not an afterthought

The same npm route works across major Arm Linux distributions, Ubuntu, Debian and CentOS among them, with a short list of prerequisites in front of it. Install curl through your package manager. Then, if Node is missing or too old, pull it from the NodeSource repository: the guide walks through fetching the setup_22.x script, piping it to bash with sudo, and installing nodejs from apt. Verify with node --version and npm --version. Only then run sudo npm install -g @openai/codex. That ordering matters more on a fresh server than on a laptop, because a machine with no Node at all will otherwise produce an error that reads like a network problem.

Verifying the install, and reading version numbers

One command confirms everything: codex --version. In Arm's guide the printed output is codex-cli 0.153.4, which tells you both that the binary is on your PATH and which release you are on. That number moves quickly, so treat any version you read on a third-party page, this one included, as a sample rather than the current release. It is still worth recording. When behaviour changes between machines, the first useful question is whether both are on the same release, and the second is whether the documentation you are following predates it. Pin the version in any team setup notes you write. It costs one line and turns an unreproducible complaint into something a colleague can check against their own machine.

Two sign-in paths, and why the choice is not cosmetic

You can authenticate by signing in with a ChatGPT account on a Plus, Pro, Team, Edu or Enterprise plan, or by supplying an OpenAI API key. Running the tool and choosing Sign in with ChatGPT handles the first. The distinction is billing, not convenience: a plan sign-in draws on your subscription allowance, while an API key routes through metered platform usage that shows up on the API dashboard instead. Teams get this wrong in both directions, either burning a personal allowance on shared automation or quietly running a metered key where a covered plan already existed. Decide deliberately, and note the choice somewhere your colleagues can read it. A single line in the project README naming which account the agent runs under has settled more billing arguments than any dashboard.

Where the reference material lives

Official documentation sits at developers.openai.com/codex/cli, with the wider Codex documentation set published under learn.chatgpt.com/docs. That site has one detail worth knowing: appending .md to a page URL returns a markdown version, and there is an llms.txt index of the full documentation tree. Both are useful if you keep local notes or feed documentation to another tool. The source repository is at github.com/openai/codex. For anything version-specific, flags, configuration keys, sandbox settings, go to those pages rather than to a blog post, because the surface changes release to release and secondhand copies age badly. That applies to this page as much as to any other: the install commands above are stable, but flags and configuration keys are exactly the sort of thing that gets renamed between releases without anyone announcing it loudly.

From nothing to a working install

  1. Check the runtime
    Run node --version and npm --version. Anything below Node 18 needs upgrading first, whether through your package manager or the NodeSource repository on Arm Linux.
  2. Install globally
    Use npm install -g @openai/codex on most systems, adding sudo on Linux, or brew install --cask codex on macOS if Homebrew already manages your other tooling.
  3. Print the version
    Run codex --version. A release number confirms the binary is on your PATH; a command-not-found means the global bin directory is missing from your shell configuration.
  4. Authenticate deliberately
    Launch the tool and choose Sign in with ChatGPT for a Plus, Pro, Team, Edu or Enterprise plan, or configure an OpenAI API key if metered platform billing is what you want.

Install questions

What are the prerequisites for the codex cli?

An OpenAI account and Node.js 18 or later. On Debian or Ubuntu you also want curl available before fetching a newer Node from NodeSource. Arm's install guide, updated 7 September 2026, lists those requirements and covers macOS alongside major Arm Linux distributions.

npm or Homebrew, does it matter?

Functionally no; operationally a little. Homebrew keeps the cask alongside your other macOS tooling and handles upgrades with everything else, while the npm global install is the route that also works on Linux. Pick whichever your machine already uses consistently.

Do I need a paid ChatGPT plan?

Signing in with ChatGPT covers Plus, Pro, Team, Edu and Enterprise plans. The documented alternative is authenticating with an OpenAI API key, which bills as metered platform usage instead. Check the official pricing pages for what your plan currently includes, since that changes.

How do I confirm which release I am on?

Run codex --version. Arm's guide shows codex-cli 0.153.4 as the printed output at the time it was written. Record the number in your team notes, because most cross-machine behaviour differences turn out to be version differences. Doing that once, while everything still works, gives you a reference point for the day it stops.

Can I read the documentation as plain text?

Yes. On learn.chatgpt.com, appending .md to a documentation page URL returns a markdown version, and an llms.txt file indexes the complete documentation tree. That is convenient for offline notes or for feeding the docs into another tool. It also makes diffing two versions of a page practical, which is the quickest way to spot what changed in a release you skipped.

Where does Begin.sh fit next to a terminal agent?

At the start, before a repository exists. Begin.sh turns a prompt, or a URL you want cloned, into a static site or Expo app you download as a zip. It provides no hosting, backend or authentication, so it complements a coding agent rather than replacing one.

Skip the install when you only need a first version

No Node version to check and nothing to put on your PATH. Describe the site, or paste a URL to clone, and Begin.sh hands back a static site or Expo app as a zip you can open in any editor.
